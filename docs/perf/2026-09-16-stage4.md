## Read the startup number as void

Load average was 101 (1-minute, 10 cores) across these runs: another browser on
this machine was using four cores of its own, plus a language server at one.
Startup is the metric that measure of contention ruins, and 4241 ms against
Stage 3b's 2988 ms says what the machine was doing, not what this code does.
**Re-measure startup on a quiet machine before quoting it anywhere.**

Idle RSS and process count survive the contention, because both are read after
a 60 s settle and neither is a race for the processor:

| Metric | Stage 3b (2026-09-12) | Stage 4 (2026-09-16) |
|---|---|---|
| Idle RSS, all processes (MB) | 1482 | 1459 |
| Process count | 9 | 9 |

So the four features of Stage 4 — the pill and extensions in the sidebar, peek,
the outside-link window, routing rules and the box's commands — add no process
and no idle memory at all. That is the answer to the first two of the four
questions the project asks before a feature is built, taken rather than argued:
a peek and an outside link are ordinary tabs that only exist once opened, and
the rest is Views and a side table.
